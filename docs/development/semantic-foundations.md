# RPL 的语义基础：具体迹语义与值流投影

> 本文给出 RPL 匹配机制的语义基础。核心立场是：**原始（具体）语义保持不变——程序语义仍是"基本操作迹的集合"；RPL 并不直接工作在这层具体语义上，而是工作在一个投影 α 上，即"值流投影"（value-flow projection）。** RPL 的 soundness / completeness 都相对这个投影陈述；而这个投影相对具体语义的**忠实性（faithfulness）**是一条独立的、目前部分成立的可证命题。
>
> 本文取代较早的 [`trace-semantics.md`](./trace-semantics.md)（那一版是初步设计说明）；本文是它的精确化，加入了抽象函数 α、交换图、以及 soundness/completeness 的证明框架。文中"可证"指有明确证明思路、"开放"指尚未形式化；所有事实以当前代码为准。

---

## 摘要

把 RPL 放到抽象解释的框架下看：

1. **具体域**：程序语义 = 基本操作迹（偏序迹）的集合，记为 ⟦Q⟧。这一层**不改动**。
2. **抽象域**：值流图 VF(Q)——节点是操作，边是流依赖（RAW，即 def-use）。
3. **抽象函数 α**：把具体迹投影到"值经 place 从写流向读"这个子字母表，并商掉 local 重命名与无关语句顺序。
4. **匹配**：模式 P 是开放值流图，⟦P⟧ᶜ = 其一切闭实例；"Q 匹配 P" = ∃θ. θ(P) ⊑ VF(Q)（子图嵌入）。
5. **Soundness / Completeness** 相对 α 陈述，并可证（结构层）。
6. **忠实性**：α 是否忠实反映具体语义，由一张交换图刻画；它在**忠实片段**上成立，在**四个缺口**处不成立。

---

## 1. 三层架构总览

| 层 | 对象 | 命题 | 状态 |
|---|---|---|---|
| 具体层（concrete） | 迹集合 ⟦Q⟧ | （地基，不改动） | — |
| 抽象层（abstract） | 值流图 VF(Q) | 匹配 = 子图嵌入 | RPL 实际工作层 |
| 忠实性（faithfulness） | α̂(⟦Q⟧) vs VF(Q) | 交换图是否交换 | 忠实片段成立，四缺口不成立 |

一句话：**具体语义不变，只是先投影、再在投影上匹配。**

---

## 2. 具体语义：迹语义（地基，不改动）

程序 Q 的语义建模为带标签迁移系统 ⟨S, s₀, →⟩，→ ⊆ S × Σ × S，Σ 是基本操作集。Q 的迹集：

⟦Q⟧ = { a₁a₂… | s₀ —a₁→ s₁ —a₂→ … } ⊆ Σ^∞

两个要点（细节见 [`trace-semantics.md`](./trace-semantics.md)）：

- **偏序迹而非全序**：独立动作可交换，语义取 Mazurkiewicz 迹（依赖偏序），而非某个线性化。
- **结构化事件而非扁平事件**：一条语句是复合事件（读→算子→写），要保留因果、冲突、嵌套，否则会丢关联。

**本文的关键声明：这一层就是"原始语义"，全文不再修改它。** 下面做的所有事，都是在这一层之上定义投影、并在投影上做匹配。

---

## 3. 值流投影 α（抽象）

### 3.1 子字母表 Σ_VF

从 Σ 里只保留两类事件：

- `wr(p)`：写 place p；
- `rd(p)`：读 place p；

以及连接它们的**流依赖**因果："某个 wr(p) 到达某个 rd(p)"（reaching definition）。

> 注意是"值**经由** place 从写流向读"，不是"值在 place 之间流动"——SSA 里 place 的身份就是值的身份，def-use 链就是"同一 place 被写、再被读"。

### 3.2 静态值流图 VF(Q)

对函数体 Q（优化 MIR），**静态抽取**出值流图：

- V = Q 的语句/终结符（节点）；
- λᵥ(v) = 操作种类 + 操作数结构（哪个位置读、哪个位置写）；
- E = **RAW 边** `(u → v, ℓ)`：u 写 ℓ、v 读 ℓ、且 u 是 ℓ 在 v 处的到达定值。

这就是 RPL 的 DDG 部分（`DataRdep` 边，[`graph.rs`](../../crates/rpl_mir_graph/src/graph.rs) 的 `update_deps` 用"就近写→读"构造）。

### 3.3 商掉什么

α 把 VF(Q) 看成**同构类**，商掉：

1. **local 重命名**（α-等价）：`_1` 和 `_9` 换名不影响值流结构；
2. **无关语句顺序**：VF 里没有语句线性顺序，只有 def-use 偏序。

于是 `α(Q) = α(Q')` ⟺ Q 与 Q' 值流结构相同、只差命名和无关顺序。

### 3.4 α 的双重角色（关键）

投影 α 有两个落点，二者必须区分：

- **动态投影 α̂**：作用于**迹**，把一次执行迹投影成它的 def-use 结构（α̂ : D → A）；
- **静态抽取 VF**：作用于**程序语法**，从 MIR 直接建值流图（VF : Prog → A）。

"值流投影"这个词在两种语境下都用，但它们的**关系**（是否一致）正是忠实性要回答的问题——见下一节。

## 4. 交换图与忠实性

```
          ⟦·⟧
   Q ────────────────→  ⟦Q⟧        具体迹集合（地基）
   │                      │
 VF│                      │ α̂        把迹投影到 Σ_VF
   ↓                      ↓
 VF(Q) ───────────────→  α̂(⟦Q⟧)     值流结构
```

**忠实性（faithfulness）**定义为两条路径一致：

α̂(⟦Q⟧) = VF(Q)

即：**把真实执行迹投影到值流事件，得到的结果 = 从 MIR 语法静态建出来的值流图。** 当且仅当这个等式成立，静态匹配才有行为语义的正当性（匹配到的东西真的对应某次执行的值流）。

**四个缺口 = 这个等式不成立的地方**（详见第 8 节）：

1. 控制依赖缺失；
2. WAR / WAW 缺失（只有 RAW）；
3. 别名 / 内存模型缺失；
4. 循环折叠（深度-1）。

在**没有这四个缺口**的忠实片段上，交换图成立；在其外，不成立。这就是"soundness 的边界"的精确来源。

## 5. 匹配与模式语义（在投影上）

### 5.1 模式的抽象语义

模式 P 是**开放**值流图（含 local/类型/常量/位置元变量）。定义：

⟦P⟧ᶜ = { θ(P) : θ 是合法替换 }

即 P 的一切闭实例的集合。

### 5.2 子图嵌入 ⊑

`G ⊑ G'` ⟺ 存在单射 φ: V(G) → V(G')，满足

- 标签保持：λᵥ'(φ(v)) = λᵥ(v)；
- 边保持：每条 `(u → v, ℓ) ∈ E(G)` 对应 `(φ(u) → φ(v), ℓ) ∈ E(G')`。

### 5.3 匹配关系 M

**"Q 匹配 P"** ⟺ ∃θ. θ(P) ⊑ VF(Q)。

这就是 RPL 匹配的全部语义内容：在值流图上做一次子图嵌入，元变量通过 θ 绑定到具体 place。

## 6. Soundness & Completeness（相对 α）

### 6.1 Soundness（结构层，可证）

> **定理（结构 soundness）。** 若 M(P, Q)，则 RPL 报告出的 (θ, φ) 是合法嵌入：θ(P) ⊑ VF(Q)。

**证明思路**——把匹配器四组检查逐一对应到嵌入条件：

| 嵌入条件 | 匹配器检查 |
|---|---|
| 节点标签保持 | `match_stmt_inner` → `match_statement_or_terminator` 逐种类比对 |
| 边保持 + 边标签一致 | `match_ddg` 要求 `mir_ddg.get_dep(φ(loc), φ(dep)) == θ(ℓ)` |
| θ 一致替换 | `MetaBindings` 的 `merge_snapshot` / `bind_adt_def` 冲突即拒绝 |
| φ 单射 | `CountedMatch` / `mir_statements[bb].match` / `used_defs` 禁止复用 |

**推论（α-不变性，全文最有语义分量的一句）：**

> **定理（α-不变性）。** 若 α(Q) = α(Q')，则对任意 P，M(P,Q) = M(P,Q')。

匹配结果只依赖值流投影，与 local 命名、无关语句排布无关。这是"RPL 建立在值流语义上"的精确表述。

### 6.2 Completeness（结构层，可证，带 caveat）

> **定理（结构 completeness）。** 若 ∃θ. θ(P) ⊑ VF(Q)，则 M(P, Q) 为真（RPL 找到至少一个匹配）。

**证明思路**：`build_candidates` 收集全候选集，`match_*_candidates` 对候选做 Cartesian 积 DFS + 回溯，候选集有限 → 终止且穷举。

**三个诚实 caveat**：

- (a) `max_results` 截断——完备性只对"截断前"成立；
- (b) 已知不完整 FIXME（如跨块重排的失败案例）——完备性相对"实现所计算的关系"，而非"理想结构关系"；
- (c) 剪枝必须保真——任何误删合法候选的启发式都会破坏完备性，需单独审计。

### 6.3 从结构层到行为层：需要忠实性

结构层 soundness/completeness **不承诺行为**。要连到行为，需要第 4 节的忠实性：

> **行为 soundness。** 若 M(P,Q) 且 α 在相关片段上忠实，则 Q 的某次执行确实展现出 θ(P) 这个值流模式。

这条在忠实片段上可证、在四缺口处不成立。它是一条**独立定理**，不是结构层的推论。

---

## 7. 三层边界

| 层 | 命题 | 状态 |
|---|---|---|
| 结构层 | M ⟺ θ(P) ⊑ VF(Q)，且 M 对 α 不变 | 可证 |
| 行为层 | α 是动态值流迹的忠实商（交换图成立） | 忠实片段可证，四缺口不成立 |
| 意图层 | 值流形状 ⟹ 真正的内存安全 bug | 不可证，委托给模式作者 + 测试可证伪 |

**这是论文里必须分开陈述的三层**：可证的部分（结构层）、部分可证的部分（行为层）、不可证但可证伪的部分（意图层）。

---

## 8. 四个缺口作为"非忠实处"

交换图 α̂(⟦Q⟧) = VF(Q) 在以下四处被破坏，每一处都可构造反例：

1. **控制依赖缺失**（代码 `FIXME: possibly missing control dependency edges`）：静态值流可能把"永不共现"的两条流嵌在一起 → 对应"分支组合走不到"的假阳性。
2. **WAR / WAW 缺失**（`update_deps` 只有 RAW）：对可变多写局部，值流对了但终值/读值语义错了。
3. **别名 / 内存缺失**（DDG 到 local 粒度为止）：`*p` 与 `*q` 同 cell 时，RPL 看成"不同 local 的写"，无内存级耦合。
4. **循环折叠**（静态单份 body）：动态是 ω-迹，静态只有一次展开，跨迭代结构不可见。

这四个缺口**不是实现 bug，而是抽象 α 的非忠实处**——精确刻画一个抽象在哪里断，本身就是静态分析论文的标准贡献。

## 9. 框架内的三个设计选择

### 9.1 动作字母表 Σ 的粒度（L1 / L2 / L3）

| 层 | Σ | 效果 |
|---|---|---|
| L1 | 语句/终结符种类 | 只保控制结构 |
| L2 | 语句 + 操作数访问 | 保值流（def-use），即本文 α |
| L3 | 抽象机内存事件 | 精确但触底未定论的内存模型 |

RPL 停在 **L1.5**：节点是 L1（语句），但 DDG 边从 L2 的访问动作（`Access`/`RWCStates`）推导。本文的 α 就是把 L2 的信息**一等化**（把"值流"作为可观察、可匹配的语义对象），而非停在"中间产物"。

### 9.2 函数调用（黑盒 / 白盒 / 灰盒）

三种观点统一为"把 callee 的迹投影到不同子字母表"：黑盒（投影到 ∅）、白盒（内联 = β-替换，投影到全集）、灰盒（投影到效果摘要）。RPL 按 callee 是否可解析切换（`-Zinline-mir` 白盒；`unresolvable_generic`/`generic_drop` 等黑盒+灰盒）。

### 9.3 循环（ω-迹 vs 深度-1 展开）

`loop {B;A}` 的迹是 `(BA)^ω`，循环是 ω-对象；RPL 匹配静态单份 body，只覆盖**单次迭代内**结构，**不能**匹配跨迭代结构。这正是缺口 4 的来源，也是结构匹配器"对行为语义主动不完备"的典型案例。

---

## 10. 结论与下一步

**结论**：RPL 的语义基础是"**具体迹语义 + 值流投影 α**"两层结构——具体语义不变，匹配在投影上进行。这使 RPL 的 soundness/completeness 可以分层陈述：

- 结构层（相对 α）可证，且有 α-不变性定理；
- 行为层依赖忠实性（交换图），在忠实片段成立、在四缺口处不成立；
- 意图层不可证、只能委托给模式作者并以测试可证伪。

**下一步**（把本文落实为可验证的工作）：

1. 把第 6 节两个定理在证明助手里形式化（先做结构层 soundness/completeness + α-不变性）；
2. 把四缺口各自配一个可构造反例，作为交换图不成立的证伪测试；
3. 在忠实片段上证明行为 soundness，精确刻画片段的边界条件；
4. 若追求更完整的行为 soundness，评估"加控制依赖 / WAR·WAW / 保守别名 / 循环展开"四笔账各自的精度-复杂度代价。

> 一句话：RPL 不是"把语义改成值流"，而是"在不变的具体迹语义之上，定义一个值流投影，并在这个投影上做可证 sound/complete 的匹配"——语义的地基不塌，只是被精确地抽象了一层。
