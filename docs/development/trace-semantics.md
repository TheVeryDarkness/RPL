# 迹语义与 RPL：一种形式化视角

> 本文从**迹语义（trace semantics）**的角度，为 RPL 的"语义等价（semantic equivalence）"提供一个形式化解释框架，并据此梳理 RPL 的现有设计与该框架的对应关系，以及把"语义保持"从一句设计口号变成可证命题所缺的部分。
>
> 定位：这是一篇设计说明（design note），不是已完成的形式化证明。文中所有关于 RPL 行为的事实都以当前代码为准，所有形式化命题均为**待证**的陈述。

---

## 0. 摘要

RPL 的匹配引擎实际做的是：在**优化后的 MIR** 上，把模式（pattern）与待检程序各自建成一张 **程序依赖图（Program Dependency Graph, PDG）**——即控制流图（CFG）与数据依赖图（DDG）的合并——然后用**带约束的回溯搜索**求**子图嵌入**，并用**元变量合一（unification）**承载"模局部变量重命名"的等价。README 把这种匹配称为 *semantic equivalence*，但这一表述长期缺乏形式定义。

本文的主张是：RPL 的匹配可以严格地表述为一种**迹语义**上的关系。具体地，

1. 程序的语义是它"基本操作的（偏序）迹的集合"；
2. 模式的语义是"迹投影的可能集合"；
3. 匹配是"迹投影下的弱模拟（weak simulation）"。

在这一框架下，RPL 的每个设计参数（动作字母表 Σ 的粒度、调用的抽象、循环的处理、数据依赖边的选择）都对应一个明确的语义选择；而"语义保持"是否成立，等价于问"RPL 的图抽象是否是迹语义的一个忠实商（faithful quotient）"——后者是一个**可证、也可证伪**的命题。RPL 现有实现的四个已知缺口，恰好就是这一命题目前不成立的四个位置。

---

## 1. 动机：RPL 声称什么，实际做什么

| | 声称（README） | 实际（代码） |
|---|---|---|
| 语义 | "semantic equivalence" | 优化 MIR（`tcx.optimized_mir`，含 inline MIR）上的结构匹配 |
| 载体 | "模式与代码实例语义等价" | CFG ∪ DDG 的子图嵌入 + 元变量合一 |
| 依据 | 无形式语义 | 只有 CVE / UI 测试套件的经验验证 |

这中间存在一个概念断层：**"结构匹配"凭什么可以被称为"语义等价"？** 本文要回答的正是这个问题——不是去证明它成立，而是给出一个框架，使"它是否成立"变成一个能精确陈述、能逐条检验的问题。

## 2. 迹语义基础

### 2.1 带标签迁移系统与迹

程序 P 的语义建模为一个**带标签迁移系统（Labelled Transition System, LTS）**：

⟨S, s₀, →⟩,  → ⊆ S × Σ × S

其中 S 是状态空间（程序点 × 内存/环境），Σ 是**动作字母表**（即"基本操作"集），`s —a→ s'` 表示执行基本操作 a 后从 s 到 s'。P 的**迹集**定义为：

⟦P⟧ = { a₁a₂… | s₀ —a₁→ s₁ —a₂→ … } ⊆ Σ^∞

这是操作语义的一种观察式表述，CompCert 的 `Events`、Miri 的 tracer、RustBelt 等本质上都走这条路线。

### 2.2 全序迹 vs 偏序迹（Mazurkiewicz 迹）

字面上的"序列"是**全序**。但全序迹对**语句重排**极其敏感：两个只差在无关语句顺序上的程序会有不同迹。而程序语义中真正稳健的是**依赖偏序**——两个不共享数据的动作是可交换的（独立动作），因此语义应取它们的**偏序迹（Mazurkiewicz trace）**，即所有等价线性化的集合，而不是某个特定线性化。

> RPL 的 DDG 正是一个**偏序**结构：它把语句的源顺序抽象成 def-use 依赖，刻意忽略独立语句之间的先后。这与偏序迹的直觉一致。

### 2.3 事件结构：因果、冲突、嵌套

如果只把动作看成一个**扁平集合/序列**，会丢失三类关键信息：

1. **原子性/分组**：`_5 = Offset(_6, _7)` 是"读 `_6`、读 `_7`、算 Offset、写 `_5`"四步的一步，这四步不可分割；
2. **因果**：哪个读喂给哪个算子、哪个算子产生哪个写；
3. **冲突**：互斥分支里的动作不会出现在同一条迹中。

正确的建模对象是**带标签事件结构（labelled event structure）**，或至少是一个带**复合事件（compound event）**的偏序：

- **因果关系** `≤`：事件之间的必须先后（数据依赖、读→算→写）；
- **冲突关系** `#`：互斥事件（switch 的不同分支）；
- **嵌套/复合事件**：一条语句 = 一个复合事件，其子事件由局部因果连接。

RPL 的 `ProgramDepGraph` 正是这样一个粗粒度事件结构：语句是**节点**（保原子性），操作数关联编码为 `Access(usize, PlaceContext)` 边，数据流编码为 `DataRdep(local)` 边（保因果），控制流编码为 `Goto`/`SwitchInt` 边（部分地保冲突）。

### 2.4 模拟与双模拟

在 van Glabbeek 的 linear-time/branching-time 谱系里，我们关心的不是"两个程序迹相等"，而是"**模式能否被程序模拟**"。一个**弱模拟（weak simulation）**允许模式的一步对应程序中若干无关动作（stuttering）之后的一步。这比迹相等、甚至比强模拟都更贴合 RPL 的实际语义目标：**RPL 匹配的是程序的子结构，不是整段执行的完整迹**。

## 3. 动作字母表 Σ 的选择

"基本操作"不是 MIR 自带的，而是**由 Σ 的选择决定**的——你给 MIR 定一个小步语义，步标签就是基本操作。存在一个自然的粒度谱系：

| 层次 | Σ（基本操作） | 例子 | 效果 |
|---|---|---|---|
| L1 语句/终结符**种类** | `Offset`、`Lt`、`Call`、`SwitchInt` | `_5 = Offset(_6,_7)` 是一个事件 | 只保控制结构，对操作数全盲 |
| L2 语句 + 操作数访问 | `Read(p)`、`Write(p)`、`Op(rvalue)` | 拆成 `Read(_6), Read(_7), Op(Offset), Write(_5)` | 保值流（def-use），正是 DDG 的来源 |
| L3 抽象机内存事件 | `Alloc`、`Read(ptr,ty)`、`Write(ptr,ty)`、`Retag` | 带 provenance 的字节级读写 | 精确，但触底到 Rust **尚未定论**的内存模型 |

两个关键观察：

1. **Σ 越细，迹越接近结构、对重排越敏感**——"更底层"不自动更"语义"，反而更"结构"。降粒度换来的是刻画内存安全的能力，代价是结构失配加剧。
2. **RPL 停在 L1.5**：它以语句为节点（L1），却用 L2 的访问动作（`Access` / `RWCStates`）来推导 DDG 边。它没有真正扁平化，而是把 L2 的分解**结构化**地挂在 L1 的节点上。

## 4. RPL 在迹语义上的落点

### 4.1 语义域：优化 MIR 的程序依赖图

RPL 的语义域是 `tcx.optimized_mir`（含 inline MIR 归一化）。每个函数体被建为 `ProgramDepGraph`：

- **节点**：`StmtOrTerm(bb, i)`（语句/终结符）、`BlockEnter`/`BlockExit`（基本块）、`Local`（局部变量）；
- **边**：`Goto`/`UnwindGoto`（控制流）、`DataRdep(local)`（数据依赖）、`Access(usize, PlaceContext)`（操作数访问）、`SwitchInt(Pu128)`/`Otherwise`（分支及常量值）。

### 4.2 模式的语义：迹投影的可能集合

模式 P 是**开放**的（含 local/类型/常量/位置元变量）。它的语义不是一条迹，而是：

⟦P⟧ = { π(σ) | σ 是某程序的一条迹，π 是投影，π(σ) 是 P 在 θ 下的合法实例 }

即：**迹投影的可能集合**。元变量替换 θ 和投影 π 一起定义"哪些事件被观察、哪些被抽象掉"。

### 4.3 匹配：迹投影下的弱模拟

"程序 Q 匹配模式 P"被定义为：

> 存在 Q 的某次执行的一个**投影子迹**，在某个动作重命名/抽象 θ 下，是 P 的一个合法实例迹。

RPL 的引擎实现就是这一关系的结构近似：

- **图嵌入** = 模拟关系的结构版本（节点↔事件、边↔因果/控制）；
- **元变量合一** = 动作重命名 θ（模 α-等价）；
- **`PatEnd` 终结符** = "我不关心这之后/之外还有什么"的显式声明，使匹配成为**前缀开放的子结构查询**。

### 4.4 现有机制在框架中的位置

| RPL 机制 | 迹语义对应 |
|---|---|
| 多槽位回溯（fn/adt slot） | 在"函数集合"层面求解绑定，而非展开调用 |
| `match_ddg`（直接依赖边） | 因果关系的严格保持 |
| `flows_to`（依赖可达性） | 因果关系的**路径**保持（弱模拟的 stuttering） |
| `cfg_reaches`（控制流可达） | 纯 Σ_L1 层的路径可达 |
| `PatEnd` → `(TerminatorEdges::None, _) => true` | 前缀开放的子结构查询 |

## 5. 四个关键设计选择及其后果

### 5.1 调用：黑盒 / 白盒 / 灰盒

函数调用是"抽象"第一次介入的地方，三种观点可统一为"把 callee 的迹投影到不同子字母表"：

- **黑盒（原子事件）**：`Call(callee, args)` 是一个 Σ 事件，内部投影到 ∅；
- **白盒（内联）**：把 callee 的迹（参数实例化后）**拼接**到调用点——迹层面的 β-替换；
- **灰盒（摘要）**：调用是一个事件，但标签换成效果摘要（读写集 / 是否 sink）。

RPL 三者全用，并按 **callee 是否可解析**切换：可解析（可单态化/内联）→ 白盒（`-Zinline-mir`）；不可解析（`dyn`/函数指针/泛型未单态化/FFI）→ 黑盒 + 灰盒（`unresolvable_generic`、`generic_drop`、`bypass_on_copy` 等谓词）。内联是唯一"强语义成立"的环节（β-替换保迹），但它必然在**递归、间接调用、跨 crate** 三处失效——这三点 1:1 对应 RPL 的现有谓词。

### 5.2 循环：ω 迹 vs 深度-1 展开

`loop { B; A }` 的迹是 `(B·A)^ω`（无穷迭代），循环在迹语义里是 **ω-无限对象**。但 RPL 匹配的是**静态 MIR CFG**，它看到的循环体只有一份，从不展开、不区分第几次迭代。因此：

- 能匹配**单次迭代内**的结构；
- **不能**匹配**跨迭代**的结构（需 ≥2 次迭代才显现的模式）。

一个直接后果：模式 `{ A; B }` 若把 `;` 读成**时序序**，匹配 `loop { B; A }` 需要跨迭代边界（A 取第 k 次末尾、B 取第 k+1 次开头，是**两次迭代**）；而 RPL 把 `;` 读成**依赖偏序**——当 A、B 独立时偏序为空，`B;A` 与 `A;B` 是同一偏序，一次迭代即匹配。**这精确地区分了"序列语义"与"偏序语义"：两种语义在 `(BA)^ω` 上给出不同答案，RPL 站在偏序那一边。**

### 5.3 语句顺序：全序被坍缩成偏序

RPL 的 `;` 不是时序组合符，而是"这两个语句各自存在、且它们之间的数据依赖边必须对得上"。有依赖时，DDG 边方向间接强制了先后；无依赖时，顺序完全自由。这是它对重排鲁棒的来源，也是它的精度边界：**凡作者用 `;` 想表达"先后"、而依赖图又恰好没体现这个先后的地方，RPL 都会过度匹配**——跨迭代和跨互斥分支是同一类错位的两个特例。

### 5.4 数据依赖边：只有 RAW（流依赖）

程序依赖理论区分四种数据依赖（RAW/WAR/WAW/RAR）外加控制依赖。RPL 的 `update_deps` 只构造**流依赖（RAW）**，且是"就近写"式的单链 reaching-definition：

```text
对每个被读的 local，往前找最近的一个写，建一条 写→读 边；找不到则记为 rdep_start（来自块外）。
```

| 先后访问 | RPL 有边 | 理论上（可变变量） |
|---|---|---|
| 写→读（RAW） | ✅ 唯一有边的 | 该有 |
| 读→读（RAR） | ❌ | 不该有（读可交换） |
| 写→写（WAW） | ❌ | 该有（顺序决定终值） |
| 读→写（WAR） | ❌ | 该有（顺序决定读到的值） |

两个"补偿"使其在多数情况下无害：(1) `optimized_mir` 消除大部分死写，纯 WAW 很少存活；(2) 就近写的结构使 WAR 重排通常会改变"读绑定到哪个写"，从而被间接区分。但**真正的洞**仍在：活的 WAW（两次写都有下游可观察、中间无读绑定）会被当成可交换；更根本的是 **local 粒度 = 无别名模型**——`*p = 1; *q = 2` 在 p、q 别名时，RPL 看到的是"对不同 local 的写"，完全没有内存级耦合。

## 6. 从口号到命题：忠实商与四个缺口

有了上面的框架，"RPL 是否语义保持"就变成一个可陈述的命题：

> **命题（soundness）。** 把 RPL 的 CFG×DDG 图匹配视为迹语义的一个商（quotient）α，若 RPL 判定 P 匹配 Q，则 α(⟦Q⟧) 中存在 P 的一个合法实例迹；即图嵌入蕴含迹层的弱模拟。

这个命题**原则上可证，也必然在若干位置不成立**。而"不成立的位置"恰好与 RPL 已知的实现缺口一一对应：

1. **控制依赖缺失**（`FIXME: possibly missing control dependency edges`）——图抽象在此不忠实；
2. **WAR / WAW 缺失**（只有 RAW）——对可变多写局部不忠实；
3. **别名 / 内存模型缺失**（DDG 到 local 粒度为止）——对堆内存不忠实；
4. **循环折叠**（静态单份 body、深度-1 展开）——对 ω 迹不忠实。

因此，诚实的结论是：**RPL 目前的"语义等价"应读作"模（α-重命名、元变量实例化、语句序抽象、基本块分解、优化/内联归一化）的流依赖等价"**；它忠实于"谁的值喂给谁"，不忠实于"谁先写、谁后读、谁和谁别名"。这四个缺口不是实现 bug，而是**精度/召回权衡**的精确数学来源。

## 7. 结论与下一步工作

**结论。** 迹语义为 RPL 提供了一个正确的形式化落脚点：程序的语义 = 基本操作的偏序迹集；模式的语义 = 迹投影的可能集合；匹配 = 迹投影下的弱模拟。RPL 的 `ProgramDepGraph`（CFG ∪ DDG）正是一个粗粒度的带标签事件结构，它把 L2 的访问分解**结构化地**挂在 L1 的语句节点上，避免了扁平事件集丢失原子性/因果/冲突的问题。

**下一步。** 若要真正坐实"语义保持"，建议按以下顺序推进：

1. **显式固定 Σ**（建议 L2：语句种类 × 操作数/place/类型，这正是 `Access` + 元变量已在编码的东西）；
2. **把图匹配定义为一个（弱）模拟关系**，并给出"图嵌入 ⟹ 迹层模拟"的 soundness 陈述；
3. **逐条标注四个缺口的非忠实处**（控制依赖、WAR/WAW、别名、循环），把它们从"抽象有损"的模糊说法变成可验证的具体反例；
4. **用 CVE 套件做双向评测**：每个非忠实处应能构造出对应的 false positive / false negative 实例，作为该框架的可证伪性检验。

> 一句话：迹语义不改变 RPL 匹配引擎的现状，但它把"语义保持"从一个无法检验的口号，变成了一个可以逐格填写的表——哪一档 sound、sound 到哪一步，都将有明确的答案。
